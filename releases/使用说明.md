# HONOR 电池安全管理 · 独立控制工具 v1.0.0

单文件绿色应用 `HonorBatteryGuard.exe`（约 20 MB），**不需要荣耀电脑管家、不需要安装、不写系统目录、不装驱动**。
图标取自项目 `reference/电池.svg`。

> 适用：具备 `ACPI\PNP0C14\HWMI` 与 `root\wmi:OemWMIMethod` 的荣耀 / 华为机型。
> 本机验证环境：HONOR MagicBook Pro 14（FMB-P）/ BIOS 1.13 / Win11 26100。

---

## 1. 30 秒上手

1. 双击 `HonorBatteryGuard.exe`，在 UAC 提示里点「是」（**必须管理员**，否则写入 EC 会被拒绝）。
2. 界面会自动读出当前电量、EC 阈值和充电模式。
3. 选档位 → 点 **「应用并验证」**。
4. 想让它自动保持：点 **「随系统启动」**。

首次运行会在 exe 同目录生成 `HonorBatteryGuard.json`（档位与偏好）和 `HonorBatteryGuard.log`（日志）。

> **单实例保护**：程序同一时间只允许运行一个。重复双击不会再开一个窗口，而是把已经运行的实例提到前台；
> 若它已收进系统托盘，则弹出提示「程序已在系统托盘运行」。命令行模式（`--status` / `--apply` 等）不受此限制，可随时并发调用。

> 顶部「当前状态」面板**每分钟整点自动刷新**（由独立后台线程驱动，不受趋势验证 / 电池报告等耗时操作的干扰，必定会刷新；面板下方「更新」时间会随之跳动）；切换档位或应用后也会立即刷新。面板已改为紧凑双列布局，下方运行日志区域相应放大。
> 标题右侧同行显示管理员权限状态（绿色「管理员权限（可写 EC）」/ 红色「非管理员」提示）。

### 重要：关闭电脑管家之后

实测发现，**荣耀电脑管家主程序退出时会把 EC 阈值清零**（变成 `起充 0% / 停充 100% / mode=0`），
电池随即恢复满充。这不是工具失效，而是管家的退出动作。

因此：

- 每次关闭电脑管家后，打开本工具点一次「应用并验证」即可恢复；
- 或者保持本工具在后台运行 —— 它**每 60 秒校验一次 EC**，发现阈值被改动会自动重发，
  并在日志与气泡里记录「守护：检测到充电阈值被重置，已自动恢复」；
- 或者启用「随系统启动」，登录后自动进入守护状态。

### 关机 / 不开自启动，设置会保留吗？

**会保留，不需要每次开机都运行软件去改。**

充电上限（如家用 40→70）**不存于 Windows 注册表，也不存于本软件的 `HonorBatteryGuard.json`**——
那个 json 只是界面记住「上次选了哪个档」的偏好。真正执行并保存它的是 **EC 固件**：
主板上的嵌入式控制器，用 NVRAM **非易失地**保存阈值，完全独立于操作系统和本软件。

- Windows 侧（本工具 / 荣耀电脑管家）只是通过 WMI 把参数「下发」给 EC；
- 充不充电、充到多少，全部由 EC 自己决定，连 Windows 没启动前 EC 就已经在管；
- 关机 / 重启只是切断主机供电，EC 的 NVRAM 不掉电，阈值保持不变。

所以你关机再开机、且**不运行任何软件**，EC 仍会按上次设的上限（如办公 70→90）工作。
本工具的 60 秒守护循环存在的唯一目的，是**防御荣耀电脑管家退出时清零 EC**，
而不是因为 EC 会「忘」。

唯一会破坏持久化的情形：

- **再次运行荣耀电脑管家并退出**：它会把 EC 清零为 0→100；此后若本工具没在跑，电池就充到 100%。
  想彻底省心，要么永远别开电脑管家，要么开启「随系统启动」让它自动抢回阈值。
- **极端掉电**：电池被彻底放空且长期不插电、或刷了 BIOS/EC 固件，EC 可能回默认 0→100。

**自检方法**：设好档位后正常关机再开机（不开任何软件），插电观察电量到上限附近
`ChargeRate` 归零且数小时不再上升；或重开本工具点「状态」，看 EC 读回的是不是你设的档位
（如办公应为 `70 46 5a` = 70→90、mode2）。

## 2. 关闭窗口 / 后台行为

关闭行为只有清晰的两种，由界面上的 **「关闭窗口时隐藏到托盘」** 勾选项决定：

| 「关闭窗口时隐藏到托盘」 | 点窗口右上角 ✕ 的结果 |
|---|---|
| **不勾选（默认）** | **真正退出程序**，进程与后台守护一并停止 |
| **勾选** | 窗口隐藏到系统托盘，**后台守护继续**（每 60 秒校验阈值） |

从托盘菜单点「退出」永远会真正退出。开机自启（`--tray`）时直接隐藏到托盘常驻守护，不占用任务栏按钮。

> 界面上不再有「最小化到任务栏」这种中间态，关闭语义只有上表两种。
> 「开机启动后台守护」勾选框已与「随系统启动」按钮合并：**启用自启动 = 登录即进入托盘守护**，
> 不再提供「只重发一次就退出」的模式（荣耀电脑管家退出会清零阈值，一次性重发不足以保护电池）。

**关于托盘图标**：程序确实向 Windows 注册了托盘图标（`Shell_NotifyIcon` 返回成功，`visible=True`），
但 **Windows 11 默认会把新图标折叠到任务栏的「^ 显示隐藏的图标」里**，程序无法强制它显示在主托盘区。

- 点任务栏右下角的 `^` 展开即可看到；
- 若要常驻显示：`设置 → 个性化 → 任务栏 → 其他系统托盘图标`，把 `HonorBatteryGuard` 设为「开」；
- 想避免依赖托盘：不勾选「关闭窗口时隐藏到托盘」，程序正常显示窗口、点 ✕ 就是退出。

托盘右键菜单（状态会实时同步）：

- 打开主界面
- 当前：`家用模式 40%→70%`
- 三档快速切换：`家用模式 40% → 70%` / `办公模式 70% → 90%` / `差旅模式 95% → 100%`，**当前档位带单选标记**
- 立即校验并恢复阈值
- **随系统启动（已启用 / 未启用）**，启用时**带勾选标记**；从主界面按钮切换后也会同步
- 退出

窗口标题栏与任务栏按钮图标均为 `reference/电池.svg` 生成的电池图标。

## 3. 三档阈值

三档是**滞回区间**（起充线 → 停充线），策略由 EC 固件执行，Windows 侧只下发参数。

| 档位 | 起充 → 停充 | mode | 适用 |
|---|---|---|---|
| 家用模式 | 40% → 70% | 1 | 长期插电，最保护电池 |
| 办公模式 | 70% → 90% | 2 | 经常插拔，兼顾续航 |
| 差旅模式 | 95% → 100% | 3 | 长时间离电，接近满充 |

写入序列：`\SBCM(mode, 原 dact, start, end)` → `\SBTT(start, end)` → 回读 `\GBTT` 校验。
`dact` 从 `\GBCM` 原样带回，避免误改 EC 其它状态位。
切到更低上限时，若当前电量已高于新上限，EC **不会主动放电**，需自然消耗回落。

## 4. 状态区字段

- 电量 / 电源 / 状态：来自 `Win32_Battery` 与 `root\wmi:BatteryStatus`。
- 充电功率 `ChargeRate`：判据核心，停充时为 0。`Charging` 布尔值在 AC 在线时不可靠，界面不采信。
- 剩余 / 满充 / 设计容量、健康度、循环次数：设计容量优先读 WMI，缺失时从 `powercfg /batteryreport /xml` 取并缓存。
- `EC 充电阈值` / `EC 充电模式`：直接回读固件，是「设置是否真的写进 EC」的权威证据。
- 权限 / 自启动、WMI 实例路径。

## 5. 验证设置是否生效

两层，从快到慢：

1. **「应用并验证」（瞬时，在档位区）**：点完档位即触发，写入 EC 后**立即回读**阈值与 mode，
   `ChargeRate=0` 且电量 ≥ 上限−2% → `PASS`；低于起充线且 `ChargeRate>0` 也判 `PASS`（正常充电）；
   区间内充电 → `CHARGING`；高于上限 → `ABOVE`（EC 不主动放电）。会一并输出瞬时判定结论。
2. **「验证」（长时间，在「趋势验证」区）**：时长下拉可选 **1 / 3 / 5 / 10 / 15 分钟**（默认 3 分钟），
   固定 12 次均匀采样，实时显示进度与逐次读数，点「停止验证」可随时中断。
   判定用「容量**不上升**」而非「容量不变」——停充后电池带载会自然缓慢下降，
   旧版要求变化绝对值 ≤2 mWh 会把正常的停充误判成 `UNKNOWN`，本版已修正：
   允许 `delta ≤ max(50, 满充容量×0.1%)` 的下降，同时要求 `ChargeRate=0`。
3. **「电池报告」**（界面右上角）：生成 `powercfg /batteryreport` HTML，看长时间容量曲线。

> 「验证生效」与「趋势验证」已合并为趋势验证区里的一个「验证」按钮；
> 瞬时校验并入档位区的「应用并验证」，不再单独保留刷新按钮——状态面板每分钟自动刷新。

最直接的实机验证：用电到起充线以下再插电，观察到上限处 `ChargeRate` 归零且数小时不再上升。

## 6. 随系统启动

点「随系统启动」按钮创建一条**任务计划程序**任务（任务名即程序名，`HONOR 电池安全管理`）：

- 触发器为**登录时**（TASK_TRIGGER_LOGON），`RunLevel=HIGHEST`（交互式令牌，登录时**静默提权、不弹 UAC**）；
- 命令固定为 `"exe" --tray`：登录后**隐藏到系统托盘并常驻守护**，每 60 秒校验阈值；
- 界面按钮文字与主界面、托盘菜单的勾选状态三处同步；
- 可在「任务计划程序」控制台查看/删除该任务，按钮再次点击即关闭（删除任务）。

> 早期版本用 `HKCU\...\Run` 注册表项，但 exe 是 `requireAdministrator`，登录时 Run 项**无法提权、静默失败**，
> 所以「随系统启动」点了没效果。本版改为**任务计划程序**，登录即自动以最高权限启动守护。
> 注意：因为走任务计划程序，**首次创建任务本身**仍需要管理员权限（点按钮时已在管理员态），之后每次登录不再弹 UAC。

## 7. 命令行（高级 / 自调用）

`--noconsole` 打包，CLI 输出同时写入同目录 `last-cli-output.json`。

| 参数 | 作用 |
|---|---|
| （无参数） | 打开图形界面 |
| `--tray` | 启动后隐藏到系统托盘 + 后台守护（自启动专用） |
| `--status` | 输出完整状态 JSON |
| `--verify` | 瞬时验证 JSON |
| `--apply home\|office\|travel` | 应用档位 |
| `--silent --apply home` | 静默执行、只写日志、立即退出 |
| `--selftest` | 自检管理员 / tkinter / WMI / 托盘依赖，输出 `overall: PASS\|FAIL` |
| `--enable-autostart` / `--disable-autostart` | 开关自启动 |

例：`HonorBatteryGuard.exe --selftest` 是最快的故障定位命令。

## 8. 绿色与卸载

- 所有配置、日志、电池报告都写在 exe 同目录；目录只读时自动回退 `%APPDATA%\HonorBatteryGuard\`。
- 卸载：点「随系统启动」关闭 → 从托盘菜单「退出」→ 删除 `HonorBatteryGuard.exe` 及同目录生成的
  `HonorBatteryGuard.json` / `.log` / `last-cli-output.json` / `battery-report-*.html`。
- 不改 BIOS、不装服务/驱动、不写系统目录。

## 9. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 所有操作提示「拒绝访问」，状态区空白 | 非管理员。右键 exe「以管理员身份运行」；正常双击会弹 UAC，请点「是」 |
| 找不到托盘图标 | Windows 11 折叠了，点 `^` 展开或在任务栏设置里打开 |
| 标题栏/任务栏显示的是 Tk 羽毛图标 | 需在创建窗口前设 `AppUserModelID`，并对**顶层+父**两层 HWND 都发 `WM_SETICON`（16/32 双尺寸），已根治 |
| 点「随系统启动」没反应 / 重启后不自动启动 | 自启动走**任务计划程序**（登录触发器+最高权限），请确认点击后按钮变「已启用」，并在「任务计划程序」里能看到对应任务 |
| 托盘菜单「随系统启动」勾选不更新 | 已在每次状态刷新时 `update_menu()` 重建原生菜单，正常同步 |
| `--status` 在 cmd 里中文乱码 | 终端代码页问题，`last-cli-output.json` 是正确的 UTF-8 内容 |
| 提示未找到 `OemWMIMethod` 实例 | 机型不支持该 ACPI-WMI 通道（需 `ACPI\PNP0C14\HWMI`） |
| 切换后电量高于上限仍不下降 | 滞回设计，EC 不主动放电，属正常 |
| 管家退出后又开始充到 100% | 后台守护会在 60 秒内自动恢复；也可手动点「应用并验证」 |

## 10. 已知限制

1. 只开放三档预设，不开放任意百分比（EC 可能只接受 OEM 组合）。
2. `office` / `travel` 为避免改动用户配置未做实机切换，mode=2/3 依据社区逆向与官方档位定义；每次切换都会回读校验，失败会明确报错。
3. 仅在 BIOS 1.13 上验证；更高版本 BIOS 行为未验证。
4. Windows 11 托盘图标折叠由系统策略决定，程序无法强制显示在主托盘区。
5. exe 为 PyInstaller onefile，首次启动需约 1 秒解压到临时目录。
